After you submit

  1. GitHub Actions routes a qualifying issue to the stage owner and adds route/status labels.
  2. The owner and relevant reviewers discuss the proposal and request evidence or revisions as needed.
  3. Changes are proposed in a pull request that cites affected requirements and verification evidence.
  4. Checks and human review determine whether the change is accepted. For released artifacts, feedback can route back to the responsible earlier stage.

Important boundary: submission is not approval. There is no hosted volunteer render queue, online voting service, automatic artifact import, or automatic release progression. Notifications depend on GitHub Actions and configured repository role variables.
