Submit the contribution for human review

Option 1 — GitHub: Continue opens a GitHub issue draft. You must sign in to submit it; the name you enter above is included for credit, but is not identity-verified.

No GitHub account? We will not ask you to create one. The account-free handoff is not active yet: this page cannot send your file or link to maintainers. You may prepare a public link above, but it will not be received until the project intake service is connected. See the developer page for the required service and current status.

  1. Download the JSON packet if you want to keep a copy of your answers.
  2. Click Continue. GitHub opens an issue draft with your answers filled in. Sign in if GitHub asks.
  3. Upload your contribution to the issue: in GitHub’s issue description box, drag the source text/document, frame images, or other allowed files onto the box (or use its attachment control). Wait for each file’s upload to finish and appear in the draft. Remove anything you did not intend to share.
  4. Review the filled-in text and attached files, then click Submit new issue. The issue and its attachments are now sent to the project for triage. Nothing is submitted by this static page before you confirm on GitHub.
  5. If you are sending frame images to a video provider, upload them separately in that provider’s interface too; attaching them to the GitHub issue does not send them to the provider.
  6. For source files or structured changes that need review, you or a collaborator can open a pull request and link it in the issue.
  7. Wait for the routed stage owner and reviewers. A submitted prompt or generated take is a proposal, not an accepted render.

After you submit

  1. GitHub Actions routes a qualifying issue to the stage owner and adds route/status labels.
  2. The owner and relevant reviewers discuss the proposal and request evidence or revisions as needed.
  3. Changes are proposed in a pull request that cites affected requirements and verification evidence.
  4. Checks and human review determine whether the change is accepted. For released artifacts, feedback can route back to the responsible earlier stage.

Important boundary: submission is not approval. There is no hosted volunteer render queue, online voting service, automatic artifact import, or automatic release progression. Notifications depend on GitHub Actions and configured repository role variables.
